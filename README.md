# 磁盘守护 DiskGuard

![build](https://github.com/XiaoRui114514/DiskGuard/actions/workflows/build.yml/badge.svg)
![release](https://img.shields.io/github/v/release/XiaoRui114514/DiskGuard?display_name=tag&sort=semver)
![license](https://img.shields.io/github/license/XiaoRui114514/DiskGuard)

Windows 磁盘占用优化工具：**按所选物理磁盘分别监控忙率；任一轮只使用当前选中的单盘数据，不累加磁盘 0/1/2。达到 98% 时立即限速该盘的活跃 IO 负载**，以缓解打字和前台软件卡顿。

界面支持**简体中文 / 繁體中文 / English / 日本語 / 한국어 / العربية** 六种语言：首次启动会按系统语言预选并让你确认一次（不属于这六种语言时默认英语），之后可在设置 → 界面语言里随时切换，即时生效（阿拉伯语自动切换为从右往左排版）。

## 1. 它是怎么工作的

每秒采样两类数据：

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 磁盘忙率 / 队列 / 读写吞吐 / 响应时间 | Windows 性能计数器（PDH，`PhysicalDisk`） | 按界面所选的**单块物理盘实例**读取；排除 `_Total`，不把磁盘 0/1/2 相加。忙率 = 100% − 空闲时间占比；响应时间 = `Avg. Disk sec/Transfer` |
| **每个进程的磁盘占用百分比** | **管理员模式：ETW 内核磁盘事件**（每个 IO 的响应时间累加 ÷ 经过时间）<br>普通用户模式：按字节占比 × 磁盘忙率 估算 | "这个软件让磁盘忙了多久"，与传输量无关——大量小 IO、随机读写同样会被算成高占用 |

> 为什么不用 MB/s 判定？因为**占用率高 ≠ 传输量大**：4K 随机读写、FUA 落盘等场景下，某个进程可能只有几十 MB/s 却让磁盘几乎一直忙。按"磁盘占用百分比"判定才符合直觉。

> 为什么还要看响应时间？因为**忙率高 ≠ 卡**：忙率 100% 但每次读写只要几毫秒时，用户其实感觉不到卡，
> 这时候限速纯属帮倒忙；响应时间涨到几百毫秒，才是"点什么都卡"的那种卡死。

普通触发阈值与限速力度可在界面里调整；98% 单盘硬上限固定生效：

1. **触发**：磁盘忙率的 5 秒滑动平均 ≥ 80%，且存在磁盘占用 ≥ 30% 的进程（默认值，可改）。
   **单盘 98% 硬上限**：所选物理盘忙率达到 98% 时立即进入保护，不受紧急保护开关和前台保护开关影响；即使当前前台程序正在使用该盘，也可以限速它。系统输入法、桌面关键进程和保护名单仍不参与限速。
   可把“提前紧急保护”设得低于 98%，在硬上限前先处理负载。硬上限只看所选磁盘实例，不使用 `_Total`，也不累加磁盘 0/1/2。
   候选仍须有该盘的当前 IO 活动，避免仅仅被磁盘拖慢的输入程序被误认成负载源。若 PDH 读写速率为 0，但 ETW 仍显示所选盘有实际 IO，则继续按 ETW 判断，不会误还原。
   如果忙率来自 SSD 内部维护、内核/驱动 IO，或系统没有提供可归属到进程的 IO，用户态程序无法保证强行压到 98% 以下；此时会记录原因，不误限速无关程序。
2. **限速规则**：
   **① 只压"当前仍在产生 IO"的进程**——候选既要在历史窗口达到 ≥1 MB/s 或 ≥100 次/秒（取设置里"最小 IO 次数"与 100 的较大值），最近一个采样间隔也要达到同样门槛；
   只是"IO 被拖慢"的受害者不再当选；
   **② 98% 单盘硬上限**——达到上限后可限速正在使用该盘的前台程序；输入法、桌面关键进程和保护名单仍硬保护；
   **③ 够用即止**——普通负载下磁盘忙率回落到 95% 以下就不再继续收紧；硬上限期间则继续处理，直到当前单盘忙率低于 98%；
   而且**继续收紧要看有没有用**：上一次收紧后忙率没有实质改善（不足 1 个百分点）时保持当前上限，
   因为普通负载下瓶颈不在这个进程时，再往下压只会让它更卡；98% 硬上限期间会继续尝试收紧。
3. **一级限速**：把该进程的**磁盘 IO 优先级降到最低**（可选同时降低 CPU 优先级）。这一步无感、可随时还原。
4. **闭环降占用**：普通负载下，5 秒后如果它的占用仍高于**目标占用（默认 20%）**、且磁盘忙率还在 95% 以上（够用即止，见上一条），
   就用 Windows 存储 QoS 的作业对象施加磁盘上限：
   带宽默认 30 MB/s，**IOPS 上限按目标进程当前的 IO 次数自适应**（压到约 2/3，最多 800、最低 8 次/秒）；
    仍不达标就每 5 秒同时收紧一次（30 → 15 → 7.5 → … 最低 2 MB/s；IOPS 继续对折，最低 8 次/秒），
    直到占用降到目标值以下、或磁盘忙率回落到 95% 以下（够用即止）、或继续收紧不再带来改善为止。
   两个上限缺一不可：**大量小 IO 的进程可能只有几百 KB/s，却因为每秒上万次 IO 把磁盘占满**，只限 MB/s 根本拦不住；
   而 USB 外置盘、快满的 SSD 这类"延迟型"磁盘，每秒几十次 IO 就能 100% 忙，固定的大上限同样等于没限，所以 IOPS 上限要贴着目标自己的 IO 次数往下压。
   少部分自带沙箱的程序（如 Chromium 系浏览器、Electron 应用）会拒绝被加入，此时自动停留在"优先级限速"。
5. **强力模式**（默认关闭，界面上可开）：已到吞吐下限仍不达标时"间歇挂起/恢复"该进程，最有效，但被限速的程序会短暂无响应。
6. **保持与还原**：普通自动限速会保持到该进程停止占用磁盘；98% 硬上限触发的限速会在所选磁盘连续两个采样回落到 95% 或以下后解除。进程退出、手动点"立即还原"、暂停监控或程序退出时也会还原。程序崩溃/被杀会写盘记录，下次启动自动修复残留限速。
   普通负载下，被限速进程切到前台会立即还原；单盘忙率达到 98% 时，为避免磁盘持续满载，会暂时覆盖前台保护。

**外壳/输入类进程永不限速**：`explorer`、`sihost`、`userinit`、`taskhostw`、`StartMenuExperienceHost`、`ShellExperienceHost`、`SearchHost`、`TextInputHost`、`ctfmon` 等负责桌面、开始菜单、搜索和输入法的进程属于硬保护，限速它们会直接表现为"打不开程序、打不了字"，因此任何模式下都不动它们。

被限速进程退出、或出现"占用达到 2 倍以上且超过触发线"的新进程时，会自动切换限速目标。

## 2. 使用方法

1. 双击 `dist\DiskGuard.exe`。建议**以管理员身份运行**（右下角按钮可一键重启提权）：

   - 管理员：使用 ETW 精确统计；可以限速 Defender、Windows 更新等系统用户态进程。
   - 普通用户：只能限速当前用户的普通进程（系统进程会提示"拒绝访问"）。

2. 「进程与限速」页签可以看到实时排行榜（每秒刷新）、当前限速对象和方式。

3. 「设置」页签可以调整：

   - 触发忙率/持续秒数、恢复忙率/持续秒数、最低速率（MB/s）
   - 触发忙率/持续秒数、恢复忙率/持续秒数
   - **触发磁盘占用（%）/ 目标磁盘占用（%）**、最小 IO 次数（次/秒）
   - **紧急保护**：忙率 ≥ 阈值（默认 98%）时立即限速，不等窗口
   - 是否降低磁盘 IO 优先级、优先级等级（极低/低）、是否同时降 CPU 优先级
   - 是否启用磁盘上限、上限值（MB/s + IOPS 同时限制）、升级等待秒数
   - 强力模式（间歇挂起）及运行/挂起毫秒数
   - 保护前台程序、保护名单（每行一个进程名）
   - 开机自动启动（**默认开启**，创建计划任务，登录后静默启动、免 UAC 弹窗）、启动时最小化到托盘（**默认开启**）、写日志、气泡提示
   - **界面语言**：简体中文 / 繁體中文 / English / 日本語 / 한국어 / العربية，选择后立即生效并自动保存（阿拉伯语为从右往左排版）

4. 关闭窗口会最小化到托盘并继续监控；托盘菜单可"暂停监控 / 立即还原全部限速 / 退出"。

5. 配置文件、日志、限速状态都在 `%LOCALAPPDATA%\DiskGuard\`（界面右下角"打开配置目录"）。

## 3. 已知边界（重要）

- **内核 "System" 进程（PID 4）无法限速**：驱动/内核发起的 IO、SSD 自身垃圾回收、部分 Windows 更新的内核路径，任何用户态程序都管不了。此时界面会提示"没有磁盘占用超过触发值的可限速进程"，不会误伤其它软件。
- **硬限速的适用范围**：作业对象限速对普通进程有效（实测 380 MB/s → 30 MB/s），但已在自身沙箱作业里的程序（Chrome/Edge、部分 Electron 应用）会返回"拒绝访问/不支持"，此时只保留优先级限速。
- **Windows Defender（MsMpEng）无法限速**：它是以 PPL 保护进程运行的，即使管理员也无法打开它修改优先级（界面会记录"拒绝访问"）。
- **精确占用统计需要管理员**：普通用户模式退回"按字节占比 × 磁盘忙率"的估算（对大批量读写准确，对小 IO 偏保守）；管理员模式下若 ETW 内核会话被系统占用，程序会依次尝试"私有会话"与"系统日志器"，都失败才降级。
- **IO 优先级查询**：极少数环境（例如受限沙箱）不允许读取进程的原始 IO 优先级，此时还原会使用系统默认值（普通优先级）。
- 本工具**不修改任何系统设置**（不改注册表、不关服务、不杀进程），只调整目标进程的 IO/CPU 优先级与吞吐上限，且随时可还原。

## 4. 常见问题

**Q: 为什么任务管理器显示磁盘 100%，但程序提示"没有可限速的进程"？**
常见于：Defender 扫描、Windows 更新的内核 IO、SysMain、SSD/HDD 自身回收。可以进一步排查是否为 SSD 性能抖动（低端 SSD 在持续写入后会出现"忙但不吞吐"的情况）。

**Q: 限速后那个程序会不会坏？**
不会。一级限速只改优先级；二级限速只是限制吞吐（类似限速下载），进程继续正常工作，只是变慢。强力模式（默认关闭）会让目标程序短暂停顿，属预期行为。

**Q: 打字/输入法会不会被限速？**
输入法和桌面关键进程始终受硬保护。普通负载下，默认设置也会保护前台程序；但所选单盘忙率达到 98% 时，如果前台应用正对该盘产生 IO，会暂时限速它，等该盘连续两个采样回落到 95% 或以下再恢复。
"保护前台程序"保护的是**整个程序**：浏览器、Electron、商店应用这类多进程软件，前台窗口所在进程的父进程与所有子进程（渲染/工具进程）都会受保护，98% 单盘硬上限触发时除外。

**Q: 怎么卸载？**
退出程序 → 关闭"开机自动启动"（或删除计划任务 `DiskGuard_AutoStart`）→ 删除 exe 与 `%LOCALAPPDATA%\DiskGuard\` 目录即可。

## 5. 源码结构 / 重新构建

```
DiskGuard.sln         解决方案（一次编译三个项目）
src/DiskGuard.Core    引擎：性能计数器采样、ETW 统计、分级限速、设置与日志
src/DiskGuard.App     WPF 界面 + 托盘（前端）
src/DiskGuard.Cli     命令行自检工具：sample / etwtest / load / throttle / prio（测试用）
tools/               图标生成、窗口截图脚本
dist/                打包输出（单文件 exe，不纳入版本库）
```

```powershell
# 编译并运行（开发模式）
dotnet build src/DiskGuard.App/DiskGuard.App.csproj -c Debug
.\src\DiskGuard.App\bin\Debug\net8.0-windows\DiskGuard.exe

# 打包单文件 exe（自包含 win-x64 / 单文件 / 压缩 / 不带 PDB，参数已写进 csproj）
dotnet publish src/DiskGuard.App/DiskGuard.App.csproj -c Release -o dist

# 自检工具（可选）
.\src\DiskGuard.Cli\bin\Debug\net8.0-windows\DiskGuard.Cli.exe sample --seconds 5
.\src\DiskGuard.Cli\bin\Debug\net8.0-windows\DiskGuard.Cli.exe load --mb 1024 --seconds 20 --buffered
.\src\DiskGuard.Cli\bin\Debug\net8.0-windows\DiskGuard.Cli.exe load --random --mb 512 --seconds 20   # 4K 随机写：磁盘忙、吞吐低
.\src\DiskGuard.Cli\bin\Debug\net8.0-windows\DiskGuard.Cli.exe throttle --pid <PID> --cap 30 --seconds 15
```

打包体积为什么是 57 MB 而不是 150 MB：自包含发布本身要带完整 .NET 运行时，项目里为此做了三件事——
托盘图标改用 `Shell_NotifyIcon` 自己实现（不再引用 WinForms，发布时按框架清单剔除 WinForms 专属程序集）、
只保留 TraceEvent 需要的 `KernelTraceControl.dll`（amd64，其余原生组件与架构副本不打包）、发行包不带 PDB。

第三方依赖：仅 `Microsoft.Diagnostics.Tracing.TraceEvent`（微软官方，MIT，用于 ETW 内核磁盘事件）。
